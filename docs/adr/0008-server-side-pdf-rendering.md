# 0008 — Server-side PDF rendering with pdfmake

**Status:** Proposed (draft from the Task 3.29 spike; finalised in Task 3.35) · **Date:** 2026-10-07 · **Design:** [§6.1](../plans/2026-10-08-phase-3-shared-services-design.md#61-documenso-integration) · **Plan:** [P3-1, P3-19, Tasks 3.29–3.30](../plans/2026-10-08-phase-3-shared-services-plan.md)

## Context
Contracts (sent to Documenso) and the Phase 4c fiche must be rendered on the server from a structured document model. Signing fields go at fixed coordinates (design §6.1). P3-1 picks pdfmake inside an edge function, with Gotenberg (HTML → PDF on the Documenso host) as the fallback behind the same `PdfRenderer` interface, if a decision rule written before measuring fails.

**Supabase limits, re-checked on 2026-10-07** ([Limits](https://supabase.com/docs/guides/functions/limits)):
- 2 s CPU per request; 256 MB memory; 150 s (Free) or 400 s (paid) wall clock.
- Function size: 20 MB when the CLI bundles it, 5 MB when bundled server-side (`--use-api`, Dashboard).
- CLI 2.98.2 (CI's pinned version) sends the eszip brotli-compressed (`EZBR`) and prints that size as « script size ». That is the size the 20 MB limit applies to.

**Decision rule** (from the plan). Adopt pdfmake only if all four hold:
- (a) every glyph renders;
- (b) the contract's warm median is ≤ 300 ms and its cold render ≤ 800 ms (≥ 2.5× headroom on the 2 s CPU limit);
- (c) the bundle is ≤ 10 MB;
- (d) field positions are deterministic.

**Measurements.** Run on 2026-10-07, on a MacBook (Apple M5), with pdfmake 0.3.11 (pdfkit 0.19.1, fontkit 2.0.4) and Inter 5.3.0. The reference documents are in `supabase/functions/_shared/pdf/spike/`.

## Decision
**Adopt pdfmake 0.3.11** (Node build, `npm:` in `supabase/functions/deno.json`). Every criterion passes:
- (a) **Passes.** The one missing glyph, U+202F, is not produced by fr-CA `Intl`, which uses U+00A0.
- (b) **Passes.** Warm median 134 ms ≤ 300 ms. Worst cold render 246 ms ≤ 800 ms, so 8× headroom on the CPU limit.
- (c) **Passes.** The uploaded size is 7.57 MB ≤ 10 MB.
- (d) **Passes.**

Inter 400 / 600 / 700 (latin) is embedded as base64 WOFF in `_shared/pdf/fonts.ts`, generated by `npm run build:pdf-fonts` (`scripts/build-pdf-fonts.ts`) from the `@fontsource/inter` devDependency. It uses **WOFF, not WOFF2**: fontkit 2.0.4 crashes while subsetting WOFF2 composite glyphs (é, à…).

## Consequences
- **Every function gets bigger, not only the PDF ones.**
  - The edge-runtime bundler embeds every npm package that the shared `deno.lock` resolves, whole: an inline `npm:` specifier gives the same result.
  - A function that imports only supabase-js grows from 7.8 MB raw / 0.93 MB uploaded to 43.8 MB / 7.37 MB.
  - A fresh worker's boot is unchanged as measured: 20–23 ms before, 21–28 ms after.
- **Deploys must keep Docker bundling**, the CLI default: `--use-api` caps the size at 5 MB. If any function nears 10 MB uploaded, vendor a pre-bundled pdfmake (this drops about 36 MB raw).
- **Task 3.30 must:**
  - register the fonts once per isolate;
  - pass images as data URLs, because pdfmake's `virtualfs` is a module-wide singleton;
  - deny URL and file access (`setUrlAccessPolicy` and `setLocalAccessPolicy` set to `() => false`);
  - keep headings with the next block (the reference contract ends page 3 with an orphan heading);
  - map U+202F to U+00A0;
  - require `signaturePage` to be the last block.
- Isolates retire after about 1 s of CPU, which locally meant a fresh worker every ~6 contracts. The cold path (about 300 ms per request) is therefore the normal case, and it is within budget.
- **Gotenberg remains the fidelity fallback** behind `PdfRenderer`. Its image was not pulled. Choosing it later needs a host on the Documenso server and `GOTENBERG_URL` (Mise en service).

## Alternatives
- **Gotenberg now:** it needs a server, a network hop and a shared secret, and the numbers do not call for it.
- **pdf-lib alone:** it has no layout engine. It stays a candidate for post-processing only.
- **`@react-pdf` in the browser** (PS Hub): rejected by design §6.1, because the PDF must come from the server.
- **WOFF2 fonts:** they crash fontkit, see above.
