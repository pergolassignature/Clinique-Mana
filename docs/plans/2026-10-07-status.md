3. **Journaux de la base de staging** (lecture seule, SQL Editor de staging). Les arguments des RPC portent des valeurs sensibles (`set_bank_details`, `set_org_secret`, bientôt le NAS) : aucun réglage ne doit les écrire dans les journaux (ADR 0004, conséquences). Ces deux requêtes remplacent les `show …` du plan (Task 4a.16, étape 4) sans échouer quand `auto_explain` ou `pgaudit` n'est pas chargé :
   ```sql
   select name, setting, unit, source
     from pg_settings
    where name in ('log_statement', 'log_min_duration_statement', 'log_min_error_statement',
                   'log_parameter_max_length', 'log_parameter_max_length_on_error')
       or name like 'auto_explain.%'
       or name like 'pgaudit.%'
    order by name;

   -- Réglages propres à un rôle ou à une base, qui remplacent ceux du serveur :
   select coalesce(r.rolname, '(tous les rôles)') as role, coalesce(d.datname, '(toutes les bases)') as base, s.setconfig
     from pg_db_role_setting s
     left join pg_roles r on r.oid = s.setrole
     left join pg_database d on d.oid = s.setdatabase
    order by 1, 2;
   ```
   Valeurs attendues :

   | Réglage | Attendu | Pourquoi |
   |---|---|---|
   | `log_statement` | `none` ou `ddl` ; **jamais** `mod` ni `all` | `mod` et `all` écrivent chaque appel de RPC, arguments compris |
   | `log_min_duration_statement` | `-1` (désactivé) | une requête lente journalisée l'est avec ses paramètres |
   | `log_parameter_max_length` | `0` ; `-1` (valeur par défaut) seulement si les deux lignes ci-dessus sont conformes et `auto_explain` absent ou à `-1` | longueur des paramètres écrits avec une requête journalisée |
   | `log_parameter_max_length_on_error` | `0` | sinon une RPC refusée (p. ex. numéro de compte invalide) écrirait ses arguments |
   | `log_min_error_statement` | indifférent (par défaut `error`) | le texte de la requête seulement ; ses paramètres suivent la ligne précédente |
   | `auto_explain.log_min_duration` | absent ou `-1` | même risque que `log_min_duration_statement` |
   | `auto_explain.log_parameter_max_length` | absent, ou `0` si `auto_explain.log_min_duration` n'est pas `-1` | |
   | `pgaudit.log` | absent, `none` ou `ddl` | les classes `read`, `write`, `function`, `misc` ou `all` écrivent les requêtes |
   | `pgaudit.log_parameter` | absent ou `off` | écrirait les arguments |
   | Seconde requête | aucune ligne qui règle un des noms ci-dessus hors de ces valeurs (les autres réglages, comme `statement_timeout` ou `search_path`, sont normaux) | un réglage par rôle (p. ex. `authenticator`) l'emporte sur celui du serveur |

   Si une valeur diffère : **ne saisir aucune vraie donnée sensible**, et donne au coordinateur le nom du réglage, sa valeur et sa colonne `source` (jamais un extrait de journal). Il faudra la corriger (tableau de bord ou support Supabase) avant de continuer.

9. **Journaux de la base, avant de saisir de vraies coordonnées bancaires** : vérifier que `log_parameter_max_length_on_error` = 0, que `log_statement` n'est ni `all` ni `mod`, et que `pgaudit.log_parameter` est désactivé, pour que les arguments des RPC (numéro de compte) n'arrivent jamais dans les journaux. Liste complète : ADR 0004 (`log_min_duration_statement`, `log_parameter_max_length`, `auto_explain.*`, `pgaudit.log`).
10. **Taux de taxes semés** :
   ```sql
   select org_id, tax, rate, effective_from, effective_to from public.tax_rates order by 1, 2, 4;
   select source, count(*) from public.audit_log where table_name = 'tax_rates' group by 1;
   ```
   Attendu : les deux taux par défaut (TPS 0,05 depuis 2008-01-01, TVQ 0,09975 depuis 2013-01-01, ouverts) et la source `migration:core_tax_rates`.
11. **Défauts des rôles copiés du modèle** (`role_permissions`) : `select role, count(*) from public.org_role_permissions group by 1 order by 1;` → `admin` 9, `admin_assistant` 2, `counselor` 1 (aucune ligne pour `provider`).
12. **Pas de 404 « immutable »** : `curl -I https://app.cliniquemana.com/assets/nexiste-pas.js` doit répondre 404 **sans** `Cache-Control: public, max-age=31536000, immutable`. Sinon, un navigateur garderait cette 404 un an : après un retour arrière (rollback) vers le déploiement qui contient ce fichier, l'app resterait cassée pour lui. Les règles d'en-têtes de Vercel ne dépendent pas du code de réponse : si l'en-tête y est, il faut revoir la règle `/assets/(.*)` avant de compter sur les rollbacks.
13. **En-têtes de cache et HSTS** : `curl -I https://app.cliniquemana.com/` doit montrer `Cache-Control: no-cache` et `Strict-Transport-Security` (Vercel l'ajoute sur ses domaines ; à confirmer sur le domaine personnalisé), et `curl -I` sur un vrai fichier de `/assets/` doit montrer `immutable`.
14. **Gestion de la clé de chiffrement, avant la Phase 4 (bloquant pour tout NAS)** : construite en Phase 4 (Task 4a.16) ; ce qu'il te reste à faire est dans « Mise en service (Phase 4, Jonathan) : données sensibles », en haut de ce document. Pour mémoire, la liste « Before Phase 4 » de l'ADR 0004 : copie de `pii_encryption_key` dans le gestionnaire de mots de passe de la clinique (procédure de restauration), vérification au déploiement qu'un texte chiffré connu se déchiffre, versions de clé et procédure de re-chiffrement.
