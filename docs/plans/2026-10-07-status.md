## Mise en service (à vérifier au premier déploiement)

1. **Sourcemaps pour Sentry** : ajouter `@sentry/vite-plugin` avec ton jeton (`SENTRY_AUTH_TOKEN` dans Vercel) et `build.sourcemap: 'hidden'` ; le plugin téléverse les cartes puis les supprime de `dist` (`sourcemaps.filesToDeleteAfterUpload`), pour qu'elles ne soient jamais servies. D'ici là, pas de sourcemaps du tout.
2. **CSP, d'abord en mode rapport** : ajouter dans `vercel.json`, sur `/(.*)`, l'en-tête `Content-Security-Policy-Report-Only` ci-dessous (remplacer l'hôte Supabase par celui de production, et `<hôte DSN Sentry>` par l'hôte de `VITE_SENTRY_DSN`, p. ex. `o123.ingest.us.sentry.io`). Le passer en `Content-Security-Policy` après une à deux semaines sans rapport inattendu. `'unsafe-inline'` pour les styles : sonner insère une balise `<style>` à l'exécution.

   ```
   default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https://vnmbjbdsjxmpijyjmmkh.supabase.co; font-src 'self'; connect-src 'self' https://vnmbjbdsjxmpijyjmmkh.supabase.co wss://vnmbjbdsjxmpijyjmmkh.supabase.co https://<hôte DSN Sentry>; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'; report-uri https://<hôte DSN Sentry>/api/<projet>/security/?sentry_key=<clé publique>
   ```

3. **Pas de 404 « immutable »** : `curl -I https://<domaine>/assets/nexiste-pas.js` doit répondre 404 **sans** `Cache-Control: public, max-age=31536000, immutable`. Sinon, un navigateur garderait cette 404 un an : après un retour arrière (rollback) vers le déploiement qui contient ce fichier, l'app resterait cassée pour lui. Les règles d'en-têtes de Vercel ne dépendent pas du code de réponse : si l'en-tête y est, il faut revoir la règle `/assets/(.*)` avant de compter sur les rollbacks.
4. **HSTS sur staging** : `curl -I https://<staging>` doit montrer `Strict-Transport-Security` (Vercel l'ajoute sur ses domaines ; à confirmer sur le domaine personnalisé).
